# Simple App v4 自託管同步規格

## 目標與範圍

v4 提供單一使用者、多裝置的離線優先同步。使用者自行部署同步伺服器；Android App 會透過 HTTPS 將本機變更推送至伺服器，並下載其他已配對裝置的變更。

本版本不提供官方雲端、多人共享、即時共同編輯、附件同步或裝置對裝置（P2P）連線。既有 JSON 匯出與匯入仍保留，作為獨立備份及救援機制。

## 資料範圍

下列資料會同步：

- 收支（`Entry`，限 `type = money`）
- 課程、上課時段與待辦
- 公告訂閱與公告關鍵字

下列資料維持裝置本機：

- 手機行事曆事件、日曆選擇與權限
- 公告快取、已讀狀態與已見公告記錄
- 通知授權、背景更新週期、僅 Wi-Fi、主題與首頁顯示偏好

本機設定不會隨同步覆蓋其他裝置。這避免一台手機的通知與網路偏好意外改變另一台裝置的行為。

## 資料一致性規則

每個可同步物件都有穩定 UUID 與同步中繼資料：

- `entityType`：資料類型。
- `entityId`：物件 UUID；訂閱使用既有 `sourceId`。
- `revision`：Hybrid Logical Clock（HLC）字串，依時間排序但可處理裝置時鐘相同或倒退。
- `deviceId`：產生該版本的裝置 UUID。
- `deleted`：是否為刪除墓碑。

兩個版本衝突時，先比較 `revision`，再以 `deviceId` 字典序作為固定裁決。勝出的版本覆蓋另一版本；未勝出的版本不會再次上傳。刪除是有版本的墓碑，與修改使用同一規則。伺服器在所有活躍裝置都已讀取後，才可清理過期墓碑與操作日誌。

課程刪除必須產生同一個交易內的相關變更：課程與其上課時段刪除，相關待辦解除課程關聯。接收端要在單一資料庫交易中套用這些變更。

## 本機同步模型

每台裝置建立不可變的 `deviceId`，並保留：

- `sync_metadata`：每個同步物件目前的版本及刪除狀態。
- `sync_outbox`：尚未獲伺服器確認的本機操作。
- `sync_state`：伺服器網址、配對後的裝置憑證、最後成功 cursor、最後同步結果。

所有可同步資料的寫入都必須經過 repository，而不是由 UI 直接操作 DAO。repository 在同一個 Room 交易中寫入領域資料、更新中繼資料並加入 outbox。

第一次啟用同步時，裝置將現有可同步資料轉成初始 upsert 操作並上傳。下載遠端資料時，依 cursor 取得新操作、在交易中合併並更新本機 cursor；遠端操作不加入 outbox。

## API v1

所有 API 僅接受 HTTPS。伺服器的基本端點為：

| 端點 | 用途 |
| --- | --- |
| `GET /healthz` | 部署與健康檢查 |
| `POST /v1/pair` | 以一次性配對碼註冊新裝置 |
| `POST /v1/sync` | 推送 outbox 操作並依 cursor 拉取新操作 |
| `GET /v1/notifications` | 前景 App 的 WebSocket 更新提示 |
| `POST /v1/devices/revoke` | 撤銷遺失或不再使用的裝置 |

`POST /v1/sync` 的請求包含協定版本、裝置 ID、上次 cursor 與操作陣列。回應包含伺服器已接受的操作 ID、新 cursor、遠端操作陣列與可顯示的錯誤碼。操作要有唯一 `operationId`，使重試具備冪等性。

當伺服器接受新的操作時，會透過 `/v1/notifications` 對其他已連線的前景裝置送出 `changes_available` 訊號。訊號不包含資料內容；App 只顯示下拉重新整理提示，使用者手動同步時才依 cursor 下載變更。App 在背景或關閉時不維持 WebSocket，回到前景後會自動同步一次。資料修改後則會由 Android 的網路背景工作自動上傳，離線時保留在 outbox 並重試。

## 驗證與安全

- 伺服器使用一次性、短效配對碼建立裝置憑證。
- 後續請求以裝置 Token 驗證；Token 僅保存在 Android Keystore 保護的本機儲存。
- 伺服器不公開資料庫連接埠，僅透過反向代理提供 HTTPS。
- 限制請求大小、操作數量與驗證失敗速率。
- 初版以傳輸加密（TLS）為必要條件。端到端加密應在協定穩定後，以相容的 payload 加密版本另行加入。

## 伺服器部署基線

參考部署使用 Go 同步服務、SQLite 持久化資料卷與 Caddy 反向代理，並以 Docker Compose 啟動。伺服器必須能在 VPS、NAS 或 Tailscale/WireGuard 私有網路中運作；不依賴 NAT 穿透或中央中繼服務。

## 版本相容性

App、伺服器與同步協定分別版本化。App 若遇到不支援的協定版本，必須停止寫入並提供明確訊息；既有 JSON 備份和離線模式仍可使用。v3 升級到 v4 時，不刪除現有使用者資料，僅新增同步中繼資料與本機設定。
